## Phase 1-3: Medallion Layers (Bronze → Silver → Gold)

Builds on the Phase 0 fragmented sources already in `SUPPLY_CHAIN`. Follows the plan's repo layout: `sql/01_bronze/`, `sql/02_silver/`, `sql/03_gold/`.

### Data flow (confirmed)
- **Existing Phase 0 entities** (orders, deliveries, shipments, tracking_events, purchase_orders, pick_operations, demand_forecast, daily_cogs, freight_invoices, overhead_allocation, freight_quotes): Bronze **ingests from** the `SOURCE_*` schemas — `INSERT INTO BRONZE.<table> SELECT ... FROM SOURCE_*`, wrapped in a VARIANT `raw_payload` + `_metadata` (source_system, load_timestamp) envelope.
- **Net-new entities** (`parts`, `plants`, `customers`, `customer_orders`, `inventory_snapshots`, `quality_events`) with no Phase 0 fragmented equivalent: synthetic data generated **directly into Bronze**, same VARIANT/`_metadata` envelope for consistency, `_metadata.source_system = 'SYNTHETIC_GENERATED'`.

### Scope decision on volume
Plan calls for 500 suppliers/2000 parts/50 plants/10K shipments/20K orders/5K quality events. To stay consistent with Phase 0's ~800-row scale (and keep this reviewable), I'll generate proportionally smaller volumes: ~50 suppliers, ~200 parts, ~20 plants, ~800 shipments (already have via Phase 0), ~500 customer orders, ~500 quality events. Flagging this trade-off now.

### 1. Bronze layer (`sql/01_bronze/create_bronze_tables.sql` + `load_bronze.sql`)
- One Bronze table per Phase-0 source table (11 tables) — ingested from `SOURCE_*`.
- Six new Bronze tables for net-new entities, generated directly.
- All tables: COMMENT, `LIFECYCLE='BRONZE'` tag, `SOURCE_SYSTEM` tag (or `SYNTHETIC_GENERATED` for net-new).

### 2. Silver layer (`sql/02_silver/`)
- `create_silver_dynamic_tables.sql`: Dynamic Tables (`TARGET_LAG='5 MINUTES'`) for `suppliers`, `parts`, `plants`, `customers`, `customer_orders`, `inventory`, `quality_events` — type-cast, deduplicated (`QUALIFY ROW_NUMBER()`), VARIANT flattened.
  - Canonical `on_time_flag` governance decision applied here: plant-dock receipt as source of truth, backorders count as late (not dropped), no artificial buffers. This is the single definition resolving Phase-0's OTD fragmentation.
- `shipment_crosswalk.sql`: the entity-resolution Dynamic Table deferred from Phase 0 — fuzzy supplier-name matching (`EDITDISTANCE`) against `SILVER.suppliers`, date-proximity joins across ERP/TMS/Supplier Portal/IoT → one `canonical_shipment_id` per physical shipment.

### 3. Gold layer (`sql/03_gold/create_gold_dynamic_tables.sql`)
- Dimensions (`TARGET_LAG='10 MINUTES'`): `dim_supplier` (SCD2), `dim_part`, `dim_plant`, `dim_customer`, `dim_date`.
- Facts: `fact_shipment` (via crosswalk + canonical on_time_flag), `fact_order_fulfillment`, `fact_inventory_snapshot`, `fact_quality_event`.
- Bridge: `bridge_supplier_part`.
- Pre-aggregate: `agg_supplier_performance` (`TARGET_LAG='15 MINUTES'`).
- Same governance metadata practice: COMMENTs, `LIFECYCLE` tags (`CANONICAL_SILVER`/`CANONICAL_GOLD`).
