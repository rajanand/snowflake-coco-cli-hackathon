## Redesign Bronze Layer: Structured vs Semi-Structured Landing

**Problem:** Every Bronze table currently uses a generic `RAW_PAYLOAD VARIANT + _METADATA OBJECT` envelope, even for sources that are already clean, structured, relational data (ERP orders, TMS deliveries, Supplier Portal shipments/POs, Finance COGS, all 6 net-new entities). Only `SOURCE_IOT_SENSOR.tracking_events` is genuinely semi-structured (nested sensor event JSON with variable noise fields) and warrants a VARIANT payload.

**Fix:** Split Bronze tables into two landing patterns:

1. **Structured landing** (16 tables: `orders`, `deliveries`, `shipments`, `purchase_orders`, `pick_operations`, `demand_forecast`, `daily_cogs`, `freight_invoices`, `overhead_allocation`, `freight_quotes`, `parts`, `plants`, `customers`, `customer_orders`, `inventory_snapshots`, `quality_events`) — typed columns mapped 1:1 from source, plus a `_metadata` OBJECT column (source_system, source_table, ingested_at) for lineage, plus `load_timestamp`. No VARIANT payload wrapper.
2. **Semi-structured landing** (1 table: `tracking_events`) — keeps `device_tag` as a typed column but `event_payload` stays VARIANT (genuinely nested/variable sensor JSON), consistent with real-world IoT ingestion.

**Files to update:**
- `sql/01_bronze/create_bronze_tables.sql` — rewrite DDL with typed columns per table
- `sql/01_bronze/load_bronze_from_sources.sql` — rewrite as explicit-column `INSERT ... SELECT` (drop `OBJECT_CONSTRUCT(*)`)
- `sql/01_bronze/generate_bronze_netnew_data.sql` — rewrite as explicit-column `INSERT` (drop `OBJECT_CONSTRUCT`)
- `sql/01_bronze/README.md` — update to document the two landing patterns and why
- `sql/02_silver/create_silver_dynamic_tables.sql` and `shipment_crosswalk.sql` — simplify: most tables now just type-cast/dedupe typed columns directly instead of parsing `raw_payload:COLUMN`; only `tracking_events` flattening keeps VARIANT extraction
- `sql/02_silver/README.md` — update to reflect the simplified flattening

**Execution:**

4. Update all affected READMEs with corrected examples

No changes needed to Gold, Semantic View, or the agent router — they consume Silver's already-typed output, which stays contractually the same.
