## Apply Snowflake Best Practices to SUPPLY_CHAIN Phase 0 Objects

Goal: bring the existing `SUPPLY_CHAIN` database/schemas/tables (Phase 0) up to Snowflake governance standards — descriptions, tags, classification, and data quality metrics — and bake these into the reusable SQL scripts in `sql/00_source_schemas/`.

### 1. Comments (descriptions)
- Add `COMMENT = '...'` to the database, every schema, every table, and key columns (primary keys, the columns involved in each source's genuine data-quality bug).
- Each source table's comment documents its specific flaw (e.g. "excludes cancelled/backorder rows from OTD denominator — inflates OTD %"), matching the plan's narrative.
- Update in place in the existing `sql/00_source_schemas/*.sql` files (comments belong in the original DDL, not bolted on after).

### 2. Tagging (governance skill)
- Create a small tag taxonomy in a new `SUPPLY_CHAIN.GOVERNANCE` schema:
  - `SOURCE_SYSTEM` (ERP / LOGISTICS_TMS / SUPPLIER_PORTAL / IOT_SENSOR / FINANCE)
  - `DATA_QUALITY_ISSUE` (free-text tag capturing each table's known bug, e.g. `EXCLUDES_CANCELLED_BACKORDER`, `PROMISED_DATE_BUFFER`, `DROPS_IN_TRANSIT`, `PARTIAL_SENSOR_COVERAGE`, `INVOICE_GAP`)
  - `LIFECYCLE` (`RAW_FRAGMENTED` — marks these as Phase-0 pre-governance tables, vs. later `CANONICAL` for Silver/Gold)
- Apply tags to each schema and table via `ALTER ... SET TAG`.
- New script: `sql/00_source_schemas/01_governance_tags.sql`.

### 3. Classification (governance skill)
- Run Snowflake's sensitive-data classification (`SYSTEM$CLASSIFY`) against each `SOURCE_*` schema to auto-detect/confirm no PII is present in this synthetic dataset, and tag accordingly (`PRIVACY_CATEGORY` / `SEMANTIC_CATEGORY` system tags via `ASSOCIATE_SEMANTIC_CATEGORY_TAGS` or reviewing results only).
- Requires checking/granting the classification privileges to `SUPPLY_CHAIN_ADMIN` (or documenting that this step needs an ACCOUNTADMIN-granted role if unavailable).
- New script: `sql/00_source_schemas/02_classification.sql` (or documented as a manual run if privileges are missing).

### 4. Data Quality Metrics (data-quality skill)
- Attach System DMFs to each source table using the `monitor-recommendations` pattern:
  - `ROW_COUNT` and `FRESHNESS` at the table/schema level
  - `NULL_COUNT` on key business columns (e.g. `erp_order_number`, `pro_number`, `asn_number`)
  - `DUPLICATE_COUNT` on natural keys
  - `UNIQUE_COUNT` where applicable
- Requires `SUPPLY_CHAIN_ADMIN` to hold `DATABASE ROLE SNOWFLAKE.DATA_METRIC_USER` (or equivalent) — will grant/check first.
- New script: `sql/00_source_schemas/03_data_quality_metrics.sql`.
- Present the generated DDL before executing (per data-quality skill's approval gate).
