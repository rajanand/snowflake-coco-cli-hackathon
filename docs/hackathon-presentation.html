01 · Summary

What we built, in six sentences

The problem

Five systems (ERP, TMS, Supplier Portal, IoT, Finance) each compute "On-Time Delivery," "Fill Rate," "Days of Inventory" and "Landed Cost" differently. Every team's number is correct by its own definition — that's the problem.

The fix

One governed native Snowflake Semantic View (9 tables, 10 relationships, 5 metrics, 5 dimensions) that resolves the fragmentation deliberately built into SOURCE_* schemas, so any persona asks a differently-worded question and gets the same answer.

On top of it

A multi-agent conversational router (agents/agent_router.py) with layered hallucination guardrails, document intelligence over supplier contract PDFs, and two deployed Streamlit-in-Snowflake apps that narrate the before/after.

Around it

Least-privilege RBAC with a genuine negative-privilege test, a free Marketplace weather dataset joined to shipment risk, a Workspace artifact of the legacy divergence queries, and real 30-day token/cost tracking.

Pipeline

Medallion architecture: fragmented sources → BRONZE (unified raw landing) → SILVER (entity-resolved canonical layer) → GOLD (28 Dynamic Tables) → SEMANTIC_MODELS.

Honest gaps

Golden-question test suite passes 2/5 live (3 fail on a disclosed REST auth-transport bug, not a metric-logic bug). Task-based automation/alerting and a packaged CoCo skill are explicitly deferred, not started.

02 · The problem

The problem, in one table

Before governance, four teams query four systems and get four different answers to "What's our On-Time Delivery rate?" — each answer is correct by that team's definition, which is exactly the problem. The governed number is stricter than every legacy answer, not just "different": the governance decision closes loopholes each source system used to look better than reality.

TeamSystemDefinitionLegacy answer
OperationsERPShip-confirm before requested date; excludes cancelled/backorder rows89.4%
LogisticsTMSDelivery before promised date (2-day carrier buffer baked in)91.3%
ProcurementSupplier PortalASN receipt before planned date; drops in-transit shipments78.6%
WarehouseIoT sensorsSensor-detected dock receipt; only ~70% sensor coveragebiased sample (65.0%, 95% CI [60.96, 68.84], n=560/800)
Governed truthSemantic ViewPlant-dock receipt vs. planned; cancelled/overdue-in-transit always count as late64.875%

The honest finding: the governed 64.875% sits inside the IoT sensor's confidence interval, far below the 78.6–91.3% band the other three systems argued over. IoT measured the right event (dock receipt) but was dismissed for thin coverage — governance adopted its definition and fixed the coverage gap through entity resolution. The answer was already in the source nobody trusted.

Fragmentation is genuine, not staged: each SOURCE_* table carries a COMMENT beginning KNOWN DATA QUALITY ISSUE: describing its specific, real flaw — see sql/00_source_schemas/*.sql. The same divergence pattern repeats for Fill Rate, Days of Inventory and Landed Cost; every legacy query plus its actually-observed result is recorded in sql/10_workspace_artifact/legacy_before_queries.sql.

03 · Architecture

Architecture, as built

Five fragmented source systems land into a unified BRONZE layer, are resolved into one canonical SILVER layer (entity resolution via shipment_crosswalk + governance-approved metric definitions), modeled dimensionally in GOLD (28 Dynamic Tables), and exposed as a governed SEMANTIC_MODELS layer — a native SEMANTIC VIEW plus Cortex Search over supplier contract PDFs. A multi-agent router and two deployed Streamlit apps consume only that governed layer, never the raw source tables. RBAC, Marketplace enrichment, and a Workspace artifact round out governance and ops.

Built Phases 0–5, 7, Governance & Ops — recorded execution evidence in each sql/ phase README   Deferred AUTOMATION (Tasks/alerting) and a packaged CoCo skill — explicit decision, not oversight

04 · Gold layer

Dimensions and the date spine are built once per refresh from SILVER; facts resolve to canonical grain via shipment_crosswalk; the bridge and aggregate tables are derived from the facts, not from SILVER directly. Together with Silver's 14 Dynamic Tables + 1 crosswalk, this is the "28 Dynamic Tables" referenced throughout this presentation.

06 · Semantic view

Semantic view & canonical metrics

CREATE SEMANTIC VIEW SUPPLY_CHAIN.SEMANTIC_MODELS.SUPPLY_CHAIN_ONTOLOGY (sql/04_semantic_view/supply_chain_ontology_semantic_view.sql) is a real Snowflake object DDL, not a YAML file only Cortex Analyst reads. Every metric/entity/dimension carries WITH SYNONYMS (...) — e.g. on_time_delivery_rate carries synonyms 'OTD','OTD%','on-time %','delivery performance','are we hitting delivery dates','schedule adherence', so business language, not column names, drives answers.

07 · Agents

Multi-agent router & guardrails

agents/agent_router.py implements SupplyChainAgentRouter: a 5-intent classifier (standard, at_risk, what_if, root_cause, document_qa) routing to 4 sub-agents — CortexAnalystClient, SimulationAgent, EvidenceTraceAgent, DocumentQAAgent. Cortex Analyst is wired to the semantic view two ways: REST (CortexAnalystClient.ask, for the CLI-connected router) and SiS-native _snowflake.send_snow_api_request (streamlit_app.py::call_cortex_analyst, for the deployed app) — same parsing logic, two transports.

Custom tools & function calling

agents/agent_router.py::AGENT_TOOLS_SCHEMA defines 4 tools, each with a name/description/parameters schema, plus build_agent_tools() returning a callable registry: ask_supply_chain_analyst, ask_supplier_contracts, run_what_if_supplier_delay, trace_root_cause.

Hallucination mitigation — layered, all in one file

  1. Constrained SQL for high-stakes intents. SimulationAgent.WHAT_IF_SQL and EvidenceTraceAgent.ROOT_CAUSE_SQL are hand-written, parameterized queries — not LLM-freeform SQL — for the what_if and root_cause intents.
  2. Semantic-view vocabulary constraint. Synonyms + metric COMMENTs constrain the LLM to one canonical measure per business concept.
  3. PreQueryValidator. Blocks empty input, input over MAX_QUESTION_LENGTH = 500 chars, non-natural-language input, and a FORBIDDEN_TERMS tuple ("drop table", "delete from", "truncate", "grant ", "alter role") before anything reaches the LLM.
  4. Confidence-threshold fallback. CONFIDENCE_THRESHOLD = 0.6 in SupplyChainAgentRouter.ask: below threshold, the response is prefixed "I'm not confident in this answer — here's what I found and why" instead of presenting a guess as fact.
  5. PostQueryEnricher. Extracts supplier IDs from a response and attaches matching Cortex Search snippets as supporting_evidence, grounding narrative claims in retrieval rather than free generation.
  6. Graceful fallback everywhere. In streamlit_app.py, every external call (call_cortex_analyst, every run_query) is wrapped in try/except with an in-panel fallback message.

10 · Marketplace & Workspace

Marketplace enrichment & Workspace artifact

Marketplace enrichment

sql/08_marketplace_enrichment/01_acquire_weather_listing.sql acquires the free "Pelmorex Weather Source: Frostbyte" listing (global name GZSOZ1LLEL). 02_region_weather_enrichment.sql builds SUPPLY_CHAIN.GOLD.v_shipment_weather_risk, joining shipments to daily weather observations by destination region and ship date, to test whether late shipments correlate with severe weather.

Reported honestly: the free listing only covers 3 of the synthetic dataset's 5 plant regions, and the correlation sample is too small in this synthetic dataset to claim a real signal. A genuine join with an honestly-reported null result, not a manufactured "insight."

Workspace artifact

sql/10_workspace_artifact/legacy_before_queries.sql collects every legacy divergence query for all 4 canonical metrics (not just OTD) plus the governed semantic-view validation query, each with its actual observed result recorded as a SQL comment — published as a Snowsight Workspace (CREATE WORKSPACE / PUT / COMMIT, since legacy Worksheets are being retired). Gives a judge a concrete, click-into artifact in Snowsight, not just a .sql file.

11 · Testing

Testing

tests/test_golden_questions.py implements 5 automated assertions: test_cross_persona_consistency (3 differently-worded questions must match within 0.01% AND share base_table/measure_name), test_zero_raw_identifiers, test_at_risk_orders, test_what_if_scenario, test_root_cause_trace.

Disclosed result: running the suite currently passes 2/5 (what_if_scenario, root_cause_trace — both pure-SQL sub-agents, routed through the REST-based CortexAnalystClient). The other 3 fail with 401 Unauthorized against the Cortex Analyst REST endpoint — an auth-transport bug specific to the CLI-connected REST client (a host-reconstruction issue for this account's region), not a problem with the semantic view or metric logic. The same metrics are independently proven correct via the deployed Streamlit app's SiS-native transport and via direct SELECT * FROM SEMANTIC_VIEW(...) queries.
